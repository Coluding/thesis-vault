Where does the gradient have to flow?

The training cost of an adapter is set by how much of the network sits in the backward graph. Solid = forward pass. Red dashed = gradient (backward). The red-shaded box is everything autograd must traverse and keep activations for.
Frozen (no weight update) Trainable Data / constant detach / no_grad boundary In the gradient graph (backward cost)

"Frozen" only switches off weight updates. Autograd still has to build the graph and retain the activations of every layer between the loss and the trainable parameters. So the deciding question is not "how many trainable parameters?" but "is the frozen base inside that span?"

1 · HyperAlign (and LoRA) — trainable weights live inside the base

The hypernetwork's factors are injected into attention layers deep inside the frozen U-Net. The only path from the loss back to those factors runs through every layer of the base. The whole base is in the gradient graph — and the base is run 2–3× per step (a frozen reference pass, the adapted pass with grad, plus HyperAlign's no-grad encoder pass).

2 · UniCon — base detached, but a heavy trainable replica

UniCon does not touch the base's weights. It runs the base once and .detach()s the captured features, so the frozen base is out of the graph. But the adapter is a full trainable copy of the decoder — so a large network is still in the backward graph. The cost is the replica (a design choice), not a forced traversal of the base.

3 · Output adapter (AVID) — base is a constant input

The base runs entirely under torch.no_grad; its output is handed to the adapter as plain data. The gradient never enters the base — backward touches only the adapter, whose size you choose. This is the most literal reading of the rule f = base + Δ: base output in, residual out.
