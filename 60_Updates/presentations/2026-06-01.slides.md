# Findings

---

## The shortcut eval would have run fully out-of-distribution

### D3 — the important one

- The adapter was only ever trained on `step_level ∈ {1, 2, 4}`; a realistic few-step rollout needs jumps **10–250× larger** (a 25-step rollout implies `step_level ≈ 40`).
- On top of the coverage gap, the raw `Linear(1, ·)` step embedding *saturates* at large step sizes — a scaling bug, not just missing data.
- **Consequence:** poor few-step rows would have been a *training-coverage artifact*, not evidence about whether shortcuts work.
- **Fixed in code:** normalised `s ∈ (0,1]` + `log2` embedding, one schedule shared by training and eval, paper-faithful `1/128 … 1` ladder.

> Caught while building the multi-step eval grid. The D3 premise — "condition on larger `d` → predict the averaged direction" — was literally never exercised in its trained regime until this fix.

## Three more findings worth flagging

### D1 · D3

::: columns
**`two_step` had no step-size signal**

The `two_step` target was a Heun prior at one hardcoded scale — `step_level` was *sampled* but the target *ignored* it, so the adapter got no gradient to behave differently per step size. → deprecated (next section).
|||
**`mask_mix` ≠ base pass-through at init**

Zero-init gate ⇒ `σ(0) = 0.5` ⇒ a 50/50 mix of base with *random* adapter output at step 0. The new `gated_residual` blend (`base + σ(gate)·Δ`) is the thesis rule `f = base + g·Δ` and is identity-at-init for free.
:::

- **Flash fires — but it is *not* what OOMs HyperAlign.** That's the double base-forward + hidden-state capture, orthogonal to attention.

# Decisions taken

---

## Two decisions resolved this week

### D3 · D2

- **Deprecate `two_step`; add a Heun-smoothness regularizer instead.** `distillation` becomes the only shortcut training mode; the Heun construction returns as an opt-in self-distillation regularizer usable on *any* run, not just shortcut.
- **Anchor MetaWorld frame-stride at the AVID convention** (`fs = 10`, contiguous read, no per-sample sampling) — matches the base DynamiCrafter pretrained `default_fs = 10`, verified against AVID's own MetaWorld data module.

## Next steps — de-risk the memory wall first

1. **Lead with the output adapter (AVID / `output_v2`) — the memory-safe family.** It runs the frozen base *once, as a black box* (no second pass, no internal-feature hooks) and just adds a residual net — unlike HyperAlign (two base passes + retained feature capture) and UniCon (capture hooks + a trainable U-Net replica). Lowest, most predictable peak memory ⇒ the de-risked path to the first `product-state` row. *(analysed)* **(D1/D2)**
2. **Run the shortcut eval grid** with the fixed step schedule — first real test of whether few-step rollout degrades gracefully vs the base. **(D3)**
3. **Diagnose the OOM on the heavyweight families.** HyperAlign OOMs even on an H100 (reported; no trace yet) — suspects are the double base-forward (`hyperalign.py:272,282`) + retained feature capture, and UniCon shares that shape by construction. Capture a real trace; condition-only hypernetwork is the candidate mitigation. **(D2)**
4. **Stand up the backup — multimodal sensory world model.** If D3/D4 underdelivers: coupled video + proprioception / depth / tactile dynamics, independent per-modality timesteps (UWM-style), three fusion variants (compositional = contribution; channel-stack & single-joint = baselines). Shortcut & multimodal are *alternatives, not layers*. **(hedge)**
