Lesson 01

Parallel Decoding Distillation

The PD loss, and what we actually borrowed

One equation, one architecture trick, and an honest audit of the target already sitting in shortcut_targets.py.

  • ~12 min
  • Deliverable D3
  • Decision-relevant
§1
the idea

One call, L steps

Classical ODE sampling walks one interval per network call. PDD trains a network that, from a single call at state X_n, emits the mean velocities of the next L intervals at once — so one call advances L steps. Everything else in the paper follows from making that idea trainable and cheap.

Why this lesson first. A PDD-inspired target is already implemented and a run is queued against the last of the compute. Before it burns, you should be able to say exactly which parts of PDD it contains. That is the whole win here.

The quantity being predicted

Not the instantaneous velocity v_t. The mean velocity over an interval:

un(Xn)  =  1/(tn+1 − tn)  ·  ∫tntn+1 vt(Xt) dt This is the velocity that makes one Euler-sized jump land exactly where fine integration lands: Xn+1 = Xn + (tn+1 − tn)·un(Xn) is exact, not an approximation (Eq. 3). The whole difficulty of few-step generation is that u is expensive to know and v is cheap.

The teacher supplies u with one solver step — Euler (1 evaluation) or Midpoint (2 evaluations). That is the entire teacher cost per loss term.

§2
Eq. 11

The loss

ℒPD(θ)  =  𝔼 ‖ ūθn(k | Xn)  −  uk( sg( X̄k ) ) ‖² ūθn(k | Xn) — the student's prediction for interval k, from one call at Xn.
n — block start, uniform on {0, L, …, N−L}.  k — an interval inside that block, uniform on {n, …, n+L−1}.
Xn ∼ ptn — drawn cheaply from data with the interpolant.
X̄k — the state reached by following the student's own predictions from Xn. This is the load-bearing symbol.
uk(·) — the teacher's mean velocity there, one Runge–Kutta step.  sg — stop-gradient.

Read it once more slowly. The student is asked: from where you are now, what will the velocity be at interval k? — and it is graded at the state its own predictions actually reach, not at a state some reference trajectory reaches. That is what on-policy means here, and it is the difference between a model accurate on the teacher's path and one accurate on the path it will actually walk at inference.

Proposition 1 states that the minimiser of this loss satisfies the parallel-decoder condition — up to Runge–Kutta error, the student's trajectory is the teacher's. No adversary, no score network, no JVP.

§3
Eq. 12–15

The architecture trick

Given a teacher of the form v_t(x) = W·H_t(x) — backbone, then one final linear layer — PDD keeps the backbone and replicates only the final linear layer, once per grid point:

ūθn(k | xn)  =  Wθk  Hθtn(xn) One shared backbone pass, N cheap heads, each initialised from the teacher's W. N is the grid size, not the block size — which is why one trained model serves many NFEs.

Two consequences worth internalising:

  • No second time coordinate. Flow-map and shortcut-style methods condition the network on both where you are and how far you're jumping. PDD indexes the jump by which head you read. The paper is explicit that this is the point: it "allows us to learn a single model that can predict any block size without the need to introduce a second time coordinate."
  • Free at inference. Generation needs only the block-average direction, so the heads collapse into one: W_{n:n+L} = Σ_k Δ_k W_k with Δ_k = (t_{k+1}−t_k)/(t_{n+L}−t_n). One fused layer per block. Zero extra inference compute versus the teacher.
Where "no JVPs" comes from. Learning a mean velocity usually forces you to regress a derivative of the velocity field — via a JVP or a finite difference, both expensive or unstable at video scale. PDD instead decomposes the mean velocity into L sub-interval predictions, and gradients through the shared backbone recover the full-interval signal in expectation. The derivative is never formed.

The loss, as the paper writes it

N   = len(t) - 1                              # grid size
n   = L_min * randint(0, N//L_min)            # sample block index
x_n = (1-t[n]) * randn_like(x) + t[n] * x     # sample the probability path
u   = student(x_n, t[n])                      # parallel predictions
h   = diff(t, dim=0)                          # step sizes
k   = randint(n, clip(n+L_max, max=N))        # sample index in the block
x_k = x_n + einsum('l,l...', h[n:k], u[n:k])  # step from n to k   <- on-policy
u_k = runge_kutta(teacher, x_k, t[k], h[k])   # teacher mean velocity
loss = mse_loss(u[k], u_k.detach())
§4
the audit

What we actually borrowed

compute_teacher_rollout_target_v_flow describes itself as "the plug-and-play-adapter transposition" of PDD. That is fair — but the transposition drops three of the four load-bearing pieces. Being precise about which:

DimensionPDD (paper)Ours (teacher_rollout)Does it matter?
Target evaluated at X̄k — reached by the student's own steps States along a teacher rollout from xt Yes. The piece Eq. 11 is built around. Ours never composes student steps, so it is never graded where it will actually be.
Teacher evaluations per loss 1 (Euler) or 2 (Midpoint) substeps=4, Euler Yes, on cost. We pay 2–4× PDD's teacher budget for a target PDD argues you needn't resolve finely.
How jump size is addressed Which head Wk you read Conditioning on log2(d) Yes, conceptually. Exactly the second time coordinate PDD positions itself against.
Velocities per forward pass L, by construction One Yes — "parallel decoding" is the name of the method, and we don't do it.
What is trained Full backbone, teacher-initialised Frozen base + small adapter By design — this is the thesis. But Prop. 1 assumes the student can represent uk; a 34M adapter over a frozen base may not, and that is open.
Bootstrapped? No — teacher target No — teacher target Shared. Neither can drift the way self-consistency can.

The honest summary: what we implemented is mean-velocity regression against a finely-integrated teacher target. That is a real and defensible objective — but it is not PDD. It shares PDD's quantity (mean velocity) and its spirit (regression, no JVP, no adversary), and none of its mechanism.

Claim discipline. "A mean-velocity teacher-rollout target, in the spirit of PDD" is supportable in the thesis. "We ran PDD" is not — the parallel decoder, the on-policy state distribution, and the fused-head inference path are all absent.

Free recall. Without looking up: write the PD loss and name every symbol. Then, in one sentence, say what would change in our implementation to make it genuinely on-policy.

ℒ_PD(θ) = E‖ ūθn(k|Xn) − uk(sg(X̄k)) ‖², with n a uniformly sampled block start, k a uniformly sampled interval inside the block, Xn from the interpolant, X̄k the state reached by the student's own predictions, uk the teacher's mean velocity from one RK step, sg the stop-gradient.

To make ours on-policy: instead of integrating the frozen base from xt to form the target, step the adapted model forward across part of the interval (detached) to reach an intermediate state, and evaluate the frozen base's single-step mean velocity there. Same teacher cost or less; a different — and, per Eq. 11, more relevant — state distribution.
